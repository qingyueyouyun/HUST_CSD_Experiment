# 设计：GateANN 自适应双模式混合 Graph Tunneling

## 1. 基线行为

GateANN 的过滤查询（`mode=8`）在 DRAM 中保留三类结构：

- `SpmatFilterStore` / `FilterStore`：每个节点的标签，用于 Pre-I/O Filtering 的
  `check_filter`；
- `FullAdjIndex`：所有节点邻居表的紧凑副本（默认 `R=32`），用于 Graph Tunneling；
- 常规内存导航结构（入口点、PQ pivots 等）。

查询沿 SSD 上的图搜索。`send_best_read_req` 在发起 I/O 前检查候选标签。如果候选
不满足过滤条件：

1. 不发起 I/O；
2. 从 DRAM 读取它的 `FullAdj` 邻居；
3. 把每个未访问邻居（无论是否匹配）以 PQ 距离插入候选池 `retset`；
4. `filter_skips` 加一。

这是一次**一跳**隧道。过滤较弱或中等时它很便宜，因为失败节点通常有匹配邻居，
候选池里仍然有有用的候选。

## 2. 为什么一跳不够

课程 YFCC 1M 索引的 Low 桶选择率中位数是 0.545%。一个节点的 32 个邻居中平均
只有约 0.17 个匹配。读到一个匹配节点后，它的邻居几乎全部失败；每个失败邻居又
展开约 32 个大多不匹配的邻居。于是 `L=320` 的候选池被不匹配顶点填满，搜索把
整个预算花在“跳过”上：原版每查询只读到 **4.38** 个匹配节点，Recall@10 只有
**34.3%**，而此时 `filter_skips` 已经约 320/查询。

瓶颈不是 SSD 带宽（I/O 很小），也不是数据集中缺少匹配顶点（约 5,450 个节点
匹配）。真正的瓶颈是**候选池被不匹配顶点占据**，按距离排序的搜索无法穿过
“不匹配的海洋”到达匹配区域。

## 3. 混合设计

补丁增加一个查询阶段的自适应双模式策略，不重建索引，也不修改磁盘格式。

### 3.1 查询级模式切换

对每个查询，用其标签集的选择率估计与 `--sel-threshold`（默认 `0.01`，即 1%）
比较：

- 估计值**高于**阈值：保持原版一跳隧道（Medium/High，以及任何弱过滤）；
- 估计值**低于或等于**阈值：启用混合中继（Low，以及部分选择率很低的 Medium 标签）。

估计值来自 4096 个节点 id 的确定性 LCG 采样，结果按查询标签集缓存。这样
Medium/High 仍走原版路径，每查询只多一次缓存查找，开销可以忽略。

### 3.2 有界多跳中继

混合模式下，一个候选失败时，代码沿 `FullAdj` 做有界广度优先遍历：

```text
失败候选
  -> 第 1 跳：它的 FullAdj 邻居
       匹配      -> 计算 PQ 距离，插入 retset
       不匹配    -> 记住，进入第 2 跳
  -> 第 2 跳：这些不匹配顶点的邻居
       ...
  -> 最多 --relay-hops（默认 3）跳、每候选 --relay-budget（默认 256）个顶点
```

只有匹配顶点会进入 `retset`。不匹配顶点只作为图上的中继：不读 SSD，也不进入
结果集。每查询还有总预算 `--relay-total-budget`（默认 4096）限制中继总量。

这保持了 GateANN 的结果语义：只有通过过滤条件、并且真正从 SSD 读到的节点才可能
进入 top-k。中继改变的是可达性，不是正确性。

### 3.3 精确有效节点位图

对每个中继邻居都调用多标签子集判断代价很高：Low 档每查询约 10 万次标签
判断。补丁为低选择率标签集在首次使用时构建**精确有效节点（valid-node）位图**
并缓存：

- 每个基础节点 1 bit（`n/8` 字节；1M 节点约 125 KiB）；
- 用现有 `passes()` 谓词扫描全部节点一次构建；
- 按查询标签集缓存；只对低选择率集合建位图；
- `--sel-threshold` 决定是否建位图；
- 计时循环开始前预热。

有了位图，中继的成员判断从“多标签有序 merge”降为一次 bit 读取。实测 Low 场景
下 `Tunnel_us` 从约 7.2 ms 降到约 2.3 ms（单次最低 1.6 ms），同 Recall 下 QPS
从约 115 升到约 267（单次最高 329）。

内存代价很小：每个低选择率标签集约 125 KiB（课程 Low 的 5 个标签集合计约
0.6 MiB）。1M 索引上每个集合构建约 8 ms；全部查询标签集预热约 38–41 ms。

### 3.4 参数

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `--hybrid` | 0 | 1 开启自适应策略 |
| `--relay-hops` | 3 | 每个失败候选的最大中继跳数 |
| `--relay-budget` | 256 | 每个失败候选的最大中继顶点数 |
| `--relay-total-budget` | 4096 | 每个查询的最大中继顶点数 |
| `--sel-threshold` | 0.01 | 选择率切换阈值 |
| `--sel-samples` | 4096 | 估计选择率的采样数 |

所有参数都可选且后置，课程适配器的命令行不变，因此默认仍运行原版。

## 5. 实测结果

环境：与课程实验相同的 WSL2 机器，1M YFCC 索引，单查询线程，beam width 8，
K=10，L=320，200 条查询，3 次独立重复取中位数。本时段的绝对延迟约为 9 月 27 日
正式实验的 1.6–2 倍（宿主电源/负载状态不同）；下面所有比较都来自同一时段。

| 配置 | L | Recall@10（%） | 延迟（μs） | 平均 I/O | 中继顶点/查询 |
|---|---:|---:|---:|---:|---:|
| 原版 | 320 | 34.30 | 771 | 4.38 | 0 |
| 混合 3-hop，budget=128 | 320 | 69.50 | 2387 | 26.43 | 1638 |
| 混合 3-hop，budget=256 | 320 | 80.15 | 3745 | 39.33 | 3277 |
| 混合 2-hop，budget=128 | 320 | 79.25 | 2770 | 46.51 | 1633 |
| 原版 | 640 | 51.80 | 1263 | 7.73 | 0 |
| 原版 | 1280 | 70.05 | 2320 | 13.95 | 0 |
| 原版 | 2560 | 83.75 | 4505 | 25.06 | 0 |

Medium（选择率 3.1%）和 High（12.0%）保持在原版路径：混合模式的 Recall、
延迟、I/O 在运行噪声内不变。

### 数字说明

- **固定 L=320** 时，混合模式大幅恢复 Recall：3-hop/budget=256 从 34.3% 提升到
  80.2%（+45.9 个百分点）。这直接支持“瓶颈是候选池被占满，而不是 SSD I/O”的
  假设。
- 代价很大：逻辑 I/O 约 8.98 倍，延迟约 4.86 倍。额外 I/O 都是真实匹配节点的
  读取；中继本身不读不匹配节点，但它会发现并排序多得多的匹配候选。
- **直接增大 L 是很强的对照**：L=2560 达到 83.75%，延迟 4.50 ms、I/O 25.06；
  L=1280 达到 70.05%，延迟 2.32 ms、I/O 13.95。L=1280 与 3-hop/budget=128 的
  Recall 基本相当（69.50% vs 70.05%），但 I/O 约为后者一半。因此本优化相对于
  直接增大 L 的方案**不是 Pareto 最优**。
- 本优化的适用区间是“固定 L、目标 Recall 约 80%”：它比 L=2560 快约 17%，
  代价是约 1.6 倍逻辑 I/O 和低 3.6 个百分点的 Recall。真实 SSD 上逻辑 I/O
  有实际成本，这个交易通常不划算；在课程的热页缓存下则接近打平。

这个负结果/有限结果是有价值的：Low 桶失败不只是图可达性问题，候选**排序与预算
分配**同样重要。后续工作应把中继遍历和距离感知的插入上限或倒排标签索引结合起来。

## 6. 正确性论证

- 节点只有经过 `compute_exact_dists_and_push` 才会进入 `full_retset`，而该函数
  只对真正从 SSD 读取的节点调用。`mode=8` 下 Pre-I/O 检查会阻止不匹配节点被读
  （除非它是匹配节点的邻居，且在被弹出时才检查）。
- 中继顶点从不读取，也从不插入 `retset`，因此不可能出现在结果中。
- 位图由与 `check_filter` 完全相同的 `passes()` 谓词构建，没有假阴性，也没有
  假阳性。
- 返回的 top-k 仍然去重并按距离排序。

## 7. 局限与后续

- 中继 BFS 是广度优先、忽略距离的，会发现很多较远的匹配节点。一个明显的后续
  实验是加距离感知的插入上限（只保留中继发现的最近 m 个匹配，m=8/16/32）。
- 位图缓存目前按标签集无限增长；生产版本应加 LRU/上限（例如 64 个集合），并
  计入内存预算。
- 模式切换使用 1% 阈值；Medium 的 1.765%–5% 标签仍在原版路径。阈值扫描
  （0.01/0.02/0.03）是验证计划的一部分。
- 结果来自一台 WSL2 机器和一个 1M 索引，不应被解读为原生 SSD 的绝对性能。
